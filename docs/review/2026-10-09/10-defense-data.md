2026-10-09, 대상 `v0.10.0`, 소스 `ede67e302a8487aecbb4d59587a8686292018cf6`. [원 데이터 보고서](01-data.md), [원 상태 보고서](04-state.md), [반대심사](07-red-data.md)를 `AGENTS.md`·원래 philosophy/invariants/versioning·checkout/agent-tasks 설계와 대조했다. 다른 defense 보고서는 읽지 않았다. 구현 수정 없이 **원 ID 33개 전부의 주장과 처방을 따로 판정**한다. 반대심사는 새 RED-A ID가 없다고 명시한다. 따라서 RED-A 신규 ID 대상은 0개이며, P01–27/Q01–12의 추가 반례는 아래 해당 원 ID에 모두 반영했다.

정상 입력의 제안 전문 소실, 겹친 CLI 쓰기, archive 대체, 손상 메타 뒤 checkout 편집본 소실, 쓰기 오류 뒤 truncate, 미해결 Git 발행은 방어할 수 없다. 반면 hash 변화 하한의 done, 명시적 GC, 난수 seed, 경로별 로컬 namespace를 모두 지식 손실 버그로 부르는 것은 기각한다. 원문이 위키에 남은 후처리 실패는 부분 적용 문제로 좁힌다. 강한 복구 원장·분산 lease·UUID·DB/CRDT 전환은 필수 조치가 아니다.

새 반례 **DEF-A-01**은 STATE-10의 “짧아져도 즉시 억제는 된다”는 제한을 깨뜨린다. 내부 fixed-time 관측에 이어 실제 CLI에서도 재현했지만, **새 주장의 최종 지위는 unvalidated — 최종 독립심사 대기**다. 원 주장에 대한 기존 판정과 신규 반례의 잠정 상향을 분리한다. 정확히는 1일 snooze의 즉시 무효이며, E4에 적힌 **7일 smoke command 자체의 실패를 관측한 것은 아니다**.

`accept`는 명시한 범위의 수용, `narrow`는 일부만 수용, `reject`는 독립 결함/필수 처방이라는 결론 기각, `defer`는 근거 또는 제품 결정 보류다. 처방의 accept는 구현 완료/시험 통과를 뜻하지 않는다. P1=작성 텍스트 소실·잘못된 발행, P2=조건부 상태 손실·실패/정합성 오류, P3=설명·점검·선택 정책이며 릴리스 차단 등급이 아니다. 같은 원인은 DATA/STATE 양쪽에서 중복 계수하지 않는다.

## 수용 기준의 논리와 남는 이견

현재 whole internal/cmd 테스트는 초록이지만 실패 조건을 넣지 않았다. 기존 checkout base 테스트는 **호출 이전 변경**, idempotent checkout은 **정상 meta**, Rename 테스트는 **메서드**, task mixed-version 테스트는 **unknown 문자열/type**를 검사한다. 이들이 G12/C09/C14/C23 반례를 반박하지 않는다. 새 테스트의 존재를 먼저 `go test <package> -list '^TestName$'`로 확인하고, 실제 barrier/fault/child process 입력과 성공/보존 집합을 검사해야 한다. 존재하지 않는 `-run`의 exit 0, 단순 `-race`, 읽을 수 있는 최종 파일 수만으로 요구를 통과시킬 수 없다.

수용되는 원자성의 하한은 **성공한 mutation 보존과 실패 시 이전 완전 bytes 또는 명확한 applied/repair 상태**다. Save의 rename은 stale snapshot을 막지 못하고, O_EXCL 빈 파일 확보는 완전 게시를 증명하지 못한다. guard는 add 이전, RMW 보호는 Load 이전부터, cleanup 결과는 원문 적용 이후라는 실제 실패 위치를 시험해야 한다. mandatory global operation ID·상시 이유 기록·모든 원본 rollback으로 확장하지 않는다.

합의하지 못한 지점은 다음과 같이 남긴다.

- **DATA-04 심각도:** 원 보고서는 높음, RED는 원문 다중 적용에 조건부 P1, 본 방어는 현재 관측을 P2로 권고한다. 오류 뒤 원문 반영/요청된 제거/링크 잔존은 입증했지만 후처리 실패 자체의 별도 복구 불능 원문 소실은 입증하지 않았다. DATA-03/05/07의 소실을 여기에 재계수하지 않는다.
- **STATE-10/DEF-A-01:** viewer가 expiry를 바꾼다는 원 표현은 기각하나 RED의 “즉시 억제만은 정상”도 1일에 대해 유지할 수 없다. 실제 CLI 관측을 최종 독립심사에서 다시 평가하기 전 새 P2 주장을 확정하지 않는다.
- **STATE-01 이행 도달성:** 고정 tmp 경합 API 실패와 자연 CLI24/24 성공이 함께 있다. 실제 process barrier 이행/미래 다중 rung의 실패·수정 효과는 미검증이다. 어느 쪽 관측으로도 모든 startup 안전/불안전을 단정하지 않는다.
- **제품 결정:** legacy snooze 만료/새 기간, 기각의 영구성, page 이력의 이름 재사용, origin snapshot/known future type verifier, canonical wiki identity와 개별 future DB guard는 구현 사실만으로 선택이 끝나지 않는다. 행렬은 최소 권고와 대안을 구분했으며 해당 defer를 최종 합의로 바꾸지 않았다.

독립 재실행을 하지 않은 material 범위는 `--sync` cache의 post-pull/search 치유(P26), 실제 두 clone edit-ID add/add와 같은 task done/dismiss 의미 합류, 강제 process-barrier migration, invalid-ts GC 입력, 모든 gate/fault 조합이다. 각 범위의 원/RED 증거 및 source 연결은 검토했으나 자체 end-to-end 검증으로 승격하지 않았다. 실제 browser JS/화면, ORT/모델·추천 품질/성능, 네트워크·인증·hooks, 실제 power loss/quota, Windows·ACL/소유·symlink/hardlink 교체 의미, 오래 운용한 사용자 wiki의 빈도도 미검증이다.
