# Canopy v0.10.0 반대 심사 — Group C: 웹·문서

대상 커밋은 `ede67e302a8487aecbb4d59587a8686292018cf6`이다. [03-web.md](03-web.md), [05-docs.md](05-docs.md)의 **WEB-01~13, DOC-01~20 전부 33개 ID와 부속 개선안**을 검토했다. 시작 시 [ID 원장](evidence/red_web-inventory.json)에 제목·원문·행·보고서 해시를 먼저 고정했다. 다른 red-team 보고서는 읽지 않았다. 기존 소스·문서·다른 보고서는 수정하지 않았다.

핵심 보존 결함을 반증하는 데 실패했다. WEB-03은 24개 폭주에 한정되지 않는다. 독립 리스닝 서버에서 **두 요청씩 24회: 성공 48개, 보존 본문 34개, 유실 14개**였다. WEB-04의 성공한 피드백 소실·일시적인 JSON 읽기 오류와 WEB-05의 거짓 읽음 성공도 재현했다. DOC-08은 Mermaid 오류 없이도 **중복 slug → 기존 페이지 show 성공 → 유일한 새 본문 삭제 → 셸 exit 0**으로 성립했다.

반면 WEB-01의 최신 브라우저 DNS 공격, WEB-02의 자동 수집을 통한 실제 침해, WEB-12의 전반적인 모바일·접근성 고장, DOC-07의 실제 injection 성공은 증명되지 않았다. WEB-11은 현재 T9를 지키는 구현에 대한 새 보증 제안이다. DOC-15의 환경 결함은 프로세스 메모리 주입 시험이며 배포 CLI 결함을 재현한 것이 아니다. 문서의 거짓 설명과 제품의 의도된 동작을 구분해야 한다.

## 판정 기준·증거·격리

`accept`는 원래 주장 범위를 채택, `narrow`는 일부만 채택, `reject`는 해당 버그/개선 주장을 기각, `defer`는 결정이나 증거가 더 필요함을 뜻한다. **버그 판정과 처방 판정은 독립적**이다. P1은 성공 뒤 재현 불가 입력 소실, P2는 실질적인 프로토콜·운영·검증 계약 오류, P3는 제한된 표시·문서·복구 문제다. 조건부 보안 영향과 실제 확인된 공격을 같은 우선도로 합치지 않는다.

`AGENTS.md`, 원래 `docs/philosophy.md`, `docs/invariants.md`를 먼저 읽었다. 특히 원본/상태/캐시 구분, 본문 쓰기와 제안 접수의 분리, 판단과 기계 검증의 구분을 기준으로 삼았다. `_meta` 변경은 self-version, 파생 DB 변경은 cache schema, 머신 로컬 비파생 상태 변경만 migration ladder라는 개발 규칙도 유지한다.

아래 표에서 H는 [독립 HTTP 관측](evidence/red_web-http-results.txt), HX는 [추가 HTTP 관측](evidence/red_web-extra-http-results.txt), R은 [독립 race 관측](evidence/red_web-race-results.txt), C는 [CLI argv·stdout·stderr·exit 전체](evidence/red_web-cli-results.json), CX는 [checkin 보충 관측](evidence/red_web-extra-results.json), J는 [shipped JS의 독립 Response 시험](evidence/red_web-js-results.txt), SJ는 [`--sync` JSON 조합](evidence/red_web-sync-json-results.json)을 가리킨다. 관측 이름은 파일 안에서 검색할 수 있다. 이 probe들의 PASS는 관측 완료이며 제품 정합성 PASS가 아니다.

기존 module cache는 의존성 읽기 재사용 경로로 명시했고 다운로드·native/model 설치를 하지 않았다. 실제 사용자 위키를 읽거나 변경하지 않았다. 시작의 읽기 전용 셸·Orca 조회는 상속 환경이었다. 전 프로세스 filesystem trace를 하지 않았으므로 **모든 도구의 실제 HOME 쓰기 0이라는 주장은 하지 않는다**. Go/Canopy 호출이 상속 HOME으로 실행된 경우는 없다. Orca lifecycle 메시지는 지시된 runtime 경로로만 보냈다.

## 한계·남은 방어·종료 상태

독립 브라우저/DNS rebinding/실제 script 실행·외부 수집 서버 요청·native form/IME/focus·accessibility tree·360/1280 layout·theme screenshot을 시험하지 않았다. ORT/model 다운로드·실제 임베딩 동시성/검색 품질·Homebrew/서비스·타 플랫폼·실제 remote Git·기기간 옛 format clone도 미실행이다. LLM activation/권한 우선순위/injection 저항·태스크 의미 만족·usability 효과는 시험하지 않았다. performance의 소형 fixture 관측은 O(N) 할당의 보강이지 production p95/RSS/브라우저 frame 보증이 아니다.

새 정책이나 처방 acceptance는 구현하지 않았다. 확인된 유실을 고치는 데도 id uniqueness, file reader visibility, concurrent writer merge는 별개 계약이며 각각 시험이 필요하다. 문서의 형용사를 좁히는 수정과 저장 계층 수리를 한꺼번에 묶을 이유는 없다. 신규 세 ID에는 방어 측 검토가 남아 있다.

자기 `review_probes/red_web`의 실행 가능한 파일은 비빌드 evidence로 보존한 뒤 제거했다. 최종 [보존·정리·Git 검증](evidence/red_web-final-check.json)에 source HEAD/index/기존 tracked status 불변, assigned 보고서 불변, scratch 제거 결과를 기록했다. source repo commit·push·릴리스·서비스 변경은 하지 않았으며, Git commit/push는 승인된 자기 임시 위키와 자기 local bare remote에서만 수행했다.
