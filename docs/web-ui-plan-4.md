> 상태: **M11–M13 전부 구현 완료** — 이 계획의 범위는 종료.
> 배경 결정은 2026-07-26 재평가에서: philosophy 원칙 12("주의도 상태다")를 선언하고도
> **본길(에이전트/CLI)의 접근은 무기록**이었고, resurface의 "잊힘"은 실제로는
> "편집 안 함"(updated 날짜)의 근사였다. second-brain.md 로드맵의 Icebox 항목
> ("reads를 resurface의 진짜 열람 신호로")을 이 계획이 승격·확장한다.

## 전제 (사용자 확정, 2026-07-26)

- **두 문만 가정한다: 웹 접근 + 에이전트 접근.** git으로 여러 지점에서 pull 후
  소비하는 것(다른 기기의 Obsidian 열람 등)은 추적 불가능하고, 추적하려 들지 않는다.
  완벽한 cross-device 주의 추적은 비-목표.
- 접근 기록을 발판으로 **web UI를 단순 뷰어에서 주의를 다루는 도구로 고도화**한다 —
  비주얼 컴포넌트 세련화 포함.

## 핵심 결정: 저장은 2계층이다 (JSONL/SQLite 질문의 답)

"접근 이벤트를 모으기에 JSON(L)이 맞나, SQLite가 나서야 하나"의 답은 **역할 분리**다.
git이 동기화하는 위키에 SQLite를 넣을 수는 없고(바이너리 머지 불가), 이벤트 전량을
JSON으로 위키에 쌓을 수도 없다(무한 성장 + 읽기마다 커밋 소음). 그래서:

| 계층 | 무엇 | 어디 | 형식 | 성격 |
|---|---|---|---|---|
| **동기화되는 진실** | 페이지별 집계 (first/last/count/등급) | 위키 `_meta/` | JSON (자체 version 필드) | 재현 불가 상태 — 기기 간 동기화, resurface/발견의 근거 |
| **머신-로컬 상세** | 개별 접근 이벤트 전량 (ts·slug·문·종류) | `$XDG_STATE_HOME/canopy/attention/<위키해시>.db` | **SQLite** | 재현 불가하지만 로컬-보강 — 타임라인·통계 등 리치 UI 전용 |

- 집계는 작고(페이지 수에 유계) 사람이 읽을 수 있으며 git으로 여행한다.
  이벤트는 크고 정밀하며 그 머신에만 남는다 — 전제상 두 문(웹 serve, 에이전트 CLI)이
  같은 머신에서 돌므로 로컬 이벤트만으로 리치 UI가 성립한다.
- 위치가 `$XDG_STATE_HOME`(≈ `~/.local/state`)인 이유: 캐시가 아니고(재구축 불가),
  data도 아니다(이력·로그 부류). XDG Base Directory의 state 정의에 정확히 부합.
- 이벤트 DB의 스키마 진화는 `PRAGMA user_version` + 관용적 additive 변경으로,
  깨야 할 때는 머신-로컬이므로 마이그레이션 사다리 rung으로 처리 가능.

### 등급 사다리 (원칙 12 확장)

```
읽음 등급:   explicit(웹 ✓/다시 읽음) > auto(웹 체류 감지) > agent(show/recall 소비)
노출(≠읽음): 검색 히트 나열 · resurface shown · 관련 페이지 제안 → 읽음 기록 안 함
```

- **agent 등급은 human 등급을 오염시키지 않는다**: 에이전트가 recall로 인용했다고
  웹의 unread 배지가 꺼지지 않는다. `IsRead()`는 human 전용으로 남는다.
- agent 집계는 별도 파일 `_meta/attention/agent-reads.json`에 둔다.
  reads.json(v1)을 v2로 바꾸지 않는 이유: **혼합 버전 안전성** — 구버전 canopy가
  reads.json을 다시 저장할 때 모르는 필드를 떨어뜨려도 agent 데이터가 소실되지 않는다.
- agent 집계는 **일 단위 양자화**: 같은 페이지를 하루에 몇 번 보든 위키 파일은 하루
  1회만 변한다(커밋 소음 억제). 정밀 횟수는 로컬 이벤트 DB가 갖는다. 그래서 agent
  집계의 카운트 필드 이름은 `days`(접촉일수)다 — 회수가 아니다.

## M12 — 주의 계기판 (instruments) — 구현 완료

접근이 *데이터로 남기 시작한 뒤* 그 데이터를 보여주는 장치들.

- **기록 페이지** (`/history`, 네비 "기록"): 일 단위로 접힌 접근 타임라인 — 페이지당
  하루 한 행(그날의 가장 강한 상호작용이 대표, 반복은 ×N), 검색 질의가 행으로
  끼어들어 **search→read 궤적이 모호한 귀속 로직 없이 그대로 보인다**. (H9)
- **페이지별 주의 패널**: 페이지 하단 접이식 "접근 기록" — 읽음 횟수·마지막 시점,
  에이전트 접촉일, 최근 이벤트 6건, **12주 스파크라인**(서버사이드 인라인 SVG —
  vendor 원칙상 JS 차트 라이브러리 없이).
- **검색 궤적 데이터**: 웹·CLI 검색 모두 질의를 이벤트로 기록(`kind=search`, slug 없음
  — 히트는 여전히 무기록, H5). CLI 검색 갭도 웹과 **같은 gaps 파일**에 door 태그로
  통합 (H10). `search --no-mark`로 무흔적 검색.
- **digest 확장**: `top_consumed` — 기간 내 실접근 상위 페이지(웹/에이전트 분해),
  이벤트 로그 실측 (G8). 회고의 "무엇을 실제로 참조하며 살았나".
- **발견 랭킹 blend**: affinity의 "최근 관심"이 `RecentAccessSlugs`(두 문 통합)로 —
  recall이 인용하는 주제가 곧 관심사다.
- **그래프 주의 히트**: 접근된 노드는 온도(0–3)만큼 글로우, 툴팁에 접근 횟수.
  데이터는 동기화되는 집계에서 — 기기가 바뀌어도 히트는 따라온다.

## M13 — 비주얼 리프레시 — 구현 완료

"숲의 계기판" 디자인 시스템. 제품 자신에게서 도출한 2색 의미론이 축이다:
**초록 = 잎(지식·구조·성장)**, **앰버 = 볕(주의·오늘·재발견)** — graph heat와
재발견 카드가 이미 품고 있던 구분을 시각 언어로 승격했다.

- **색 토큰**: 라이트 = 이끼 스민 냉회록 종이(`#f6f7f3`, 크림 아님), 다크 = 밤의 임관
  (`#121714`). 링크는 청록(`--link`)으로 초록 액센트와 구분, `--warm`(앰버)이
  주의의 색으로 신설. 변수명은 graph.js 계약대로 유지.
- **타이포**: 디스플레이 = **마루부리**(한글 부리체, OFL) — 워드마크·페이지 제목·
  "오늘의 주의"·날짜 헤더에만 절제 사용. 본문/UI = **Pretendard Variable**(tnum).
  셋 다 `static/vendor/fonts/`에 내장(~2.9MB, 라이선스 동봉) — CDN 금지 원칙 준수.
- **홈 = "오늘의 주의" 대시보드**: 날짜 eyebrow → 부리체 제목 → 검색(입구 유지) →
  **수관 밴드**(시그니처: 디렉토리별 폭=페이지 수·채움=읽음 비율, 그래프와 같은 dir
  색) → "읽음 N/M ● 오늘 K페이지 · 검색 J" 앰버 오늘-라인. 재발견 카드는 warm 톤.
- **컴포넌트 통일**: 카드(라운드 14·card 배경), 칩(테두리 호버), 포커스 링
  (`:focus-visible`), 스파크라인은 앰버로(주의의 색), 기록 타임라인 날짜는 부리체.
- **모션**: 밴드 채움 1회 애니메이션뿐. `prefers-reduced-motion` 전면 존중.
- 검증: Chrome 실화면(라이트/다크 × 홈·페이지·기록·그래프) 확인, 전 테스트 green.

## 불변식 (invariants.md H 섹션에 등재)

- **H4** agent 접근은 human 읽음 등급을 오염시키지 않는다.
- **H5** 검색 노출은 읽음이 아니다.
- **H6** resurface는 모든 문(웹·에이전트)의 최근 접근을 존중한다.
- **H7** agent 접근의 위키 기록은 일 단위 양자화된다.
- **H8** 이벤트 DB는 위키 밖 머신-로컬이고, 위키 안에는 집계 JSON만 커밋된다.

## 알려진 트레이드오프 (정직하게)

- **집계 JSON의 git 머지 충돌**: 두 기기가 같은 파일을 고치면 충돌 가능 — reads.json의
  기존 현실과 동일. 페이지별 키라 충돌 빈도는 낮고, 잃어도 주의 데이터는 치명적이지 않다.
- **읽기 명령이 위키를 dirty로 만든다**: agent 접근의 첫 일일 기록이 `_meta`를 바꾼다.
  일-양자화로 소음을 최소화했고, 이는 "주의도 동기화할 상태"라는 원칙 12의 값이다.
  무흔적이 필요하면 `--no-mark`.
- **이벤트 DB는 백업되지 않는다**: 머신을 잃으면 이벤트 상세도 잃는다. 동기화되는
  진실(집계)은 위키에 있으므로 재발견 루프는 무손실 — 잃는 것은 리치 UI의 과거 상세뿐.
