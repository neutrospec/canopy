# Canopy v0.10.0 방어·증거 중재 — Group C 웹·문서

검토 대상은 `ede67e302a8487aecbb4d59587a8686292018cf6`이다. [웹 원 보고서](03-web.md)의 WEB-01–13, [문서 원 보고서](05-docs.md)의 DOC-01–20, [RED 보고서](09-red-web-docs.md)의 RED-C-01–03과 부속 처방을 모두 심사했다. 다른 방어 보고서는 읽지 않았다. 구현·기존 문서·원/RED 보고서는 수정하지 않았다.

**방어할 수 없는 것은 성공한 제안·피드백의 유실, 상태 파일 기록 중 독자 오류, 읽음의 거짓 성공, 원본을 지우는 셸 예제다.** 두 탭의 독립 본문 60개가 모두 303을 받았지만 16개가 사라졌다. 피드백은 303 33개 중 24개가 최종 상태에 없었다. 반대로 브라우저 rebinding·스크립트 실행·원격 전송·LLM injection·전반적인 모바일 고장은 입증하지 못했다. `P1`은 재현 불가 입력의 성공 후 유실, `P2`는 실질적인 계약/검증 오류, `P3`는 제한된 표시/안내/보증 개선으로 사용한다. 조건부 보안 영향은 확인된 침해와 분리한다.

`accept`는 기재한 범위를 채택, `narrow`는 일부만 채택, `reject`는 해당 해석/대안을 기각, `defer`는 증거 또는 제품 결정이 더 필요하다는 뜻이다. **주장 판정과 처방 판정은 별개**이고, 아래 수락 기준은 미구현 제안이다. 관측용 테스트의 PASS는 관측 완료를 뜻한다. 새 제품 결함·독립 기능 제안은 추가하지 않았으므로 새 DEF-C 번호는 발급하지 않았다. 기존 ID의 반례·처방 경계·수락 시험을 정밀화했으며, 미검증 처방을 제품 수락으로 표시하지 않는다.

## 독립 증거와 재현 범위

AGENTS.md, 원 철학·불변식을 먼저 읽었다. 판단은 LLM, 구조/보존은 코드라는 역할 분담과 원본/상태/캐시 구분을 유지한다. `_meta`는 파일 self-version, 파생 검색 DB는 cache schema, 재현 불가 머신 로컬 상태만 migration ladder 대상이다. 이 리뷰의 사실/문구 정정 때문에 rung·cache schema를 바꿀 이유는 없다.

모든 Go·Canopy·시험용 Git·Node subprocess는 시작 전부터 아래 격리 환경을 받았다. 고유 fixture는 `/private/tmp/canopy-review-def-web-duv7b75v`, 실행 소스는 자기 `review_probes/def_web`만 사용했다. 기존 모듈 캐시는 명시 경로로 읽기 재사용했으며 GOPROXY/GOSUMDB를 껐다. 모델·native asset 다운로드/설치, 실제 위키·서비스·remote 호스트 변경은 하지 않았다. Git commit/push는 승인된 자기 fixture와 **자기 local bare origin**에만 수행했다.

## 수락 논리에서 반드시 남겨야 할 이견

1. **현재 불변식과 새 보증을 혼동하지 않는다.** WEB-11은 원 보고서도 현재 T9 위반이 아니라고 썼다. RED의 현재 버그 기각은 받아들이지만 provenance 개선 자체를 무가치하다고 결론내릴 증거는 없다. DOC-18 역시 구조의 효과는 보류하되 lite fallback/현재 로드맵 오류는 실제 수리 대상이다.
2. **보존 수락을 부분 기술로 대체하지 않는다.** UUID만, O_EXCL만, rename만, mutex만으로 성공 입력 보존+완전 reader visibility+복수 writer/replica까지 한 번에 보증할 수 없다. 웹+CLI probe는 이번 두 실행 모두 보존됐고, 이를 실패 실증처럼 쓰지 않는다. 반대로 이 양성 결과가 두 HTTP 요청의 소실을 무효화하지도 않는다.
3. **성공의 의미를 구분한다.** HTTP 2xx≠read 저장, show exit0≠intended body 반영, 파일 hash 변화≠요청 만족, invalid0≠unchecked0, lint exit0≠건강, i18n current≠문구 참이다. 각 acceptance는 실제 실패를 구별하는 음성 사례를 포함해야 한다.
4. **측정하지 않은 정책은 보류한다.** 지원 브라우저의 rebinding/스크립트/캐시 유출, body/time 운영 숫자, proxy/source 신뢰, expired/복수 port browser, 실제 ORT 동시성·검색 품질·p95/RSS·DOM/frame, keyboard/accessibility tree·TOC/theme computed style, LLM activation/injection/작업 성공률, 구조4과제, old clone 이행·ID 합류는 미검증이다. 소형 fixture 수치를 production 예산으로 채택하지 않는다.
5. **원 실행의 격리는 소급 보증하지 않는다.** RED-C-01의 외부 환경 이견은 남는다. 원 wrapper나 원 보고서의 zero-HOME 표현 정정은 coordinator의 후속 판단이며 이 방어에서 수행한 작업은 아니다.

## 보존 소스·재실행·종료 검증

독립 소스는 [runner](evidence/def_web-runner.py.txt), [Go probe](evidence/def_web-probe_test.go.txt), [JS Response probe](evidence/def_web-response.cjs.txt), [정적 수집기](evidence/def_web-collect.py.txt)에 비빌드 텍스트로 보존한다. 실행하려면 target HEAD에서 자기 `review_probes/def_web` 부재를 확인한 후 원 이름으로 복원한다. `DEF_WEB_REPLAY_ROOT`는 **새 `/private/tmp` fixture**, `DEF_WEB_EVIDENCE_DIR`는 **그 안의 새 evidence 폴더**로 지정하여 원 증거를 덮어쓰지 않는다. runner가 HOME/XDG/Go/Git 환경을 자식 시작 전에 지정한다. build→http→js→cli→supplement→serve→existing 순서로 실행하고 race는 별도 선택한다. 각 action은 새 이름의 fixture를 만들므로 같은 root로 action을 다시 실행하지 않는다. `collect.py`는 이 감사의 정적 증거를 만드는 도구이며 replay에 필요하지 않다. 사용 뒤 자기 scratch/fixture만 제거한다. [품질 검사 소스](evidence/def_web-quality.py.txt)와 [정리 전 검사](evidence/def_web-quality.json)는 36행의 판정/질문·표 열·링크·보존 소스 문법·명시 색의 대비 계산을 기록한다. 이는 브라우저나 새 처방의 통과 시험이 아니다.

[시작 기준선](evidence/def_web-baseline.json)과 [최종 검증](evidence/def_web-final-check.json)에 source HEAD/index/기존 tracked 내용·상태, AGENTS/철학/불변식/원·RED 보고서 해시, 자체 증거·범위·scratch 정리를 기록한다. 기존 tracked 파일의 수정/커밋/릴리스/실제 upstream 접근은 하지 않았다. 자기 `review_probes/def_web`와 자기 임시 fixture는 보존 소스/출력 회수 후 제거했다. 공용 Go cache와 다른 worker scratch·증거는 건드리지 않았다.
