# canopy 원점 검토 — v0.10.0

검토 대상은 2026-10-09의 `v0.10.0`,
`ede67e302a8487aecbb4d59587a8686292018cf6`이다. 원래 목적은 **내 지식을 오래
보존하고, LLM이 출처·내용·관계를 판단하며, 사람이 다시 찾고 가꿀 수 있는 로컬
마크다운 위키**다. 이 목적에서 원문·기억 보존, 현재 근거, 실행 가능한 지침,
실제 작업 흐름, 변경을 검증하고 배포하는 능력을 검토한다.

**검토·개선안 작성 완료:** 영역별 검토 6개, 반박 3개, 재반박 3개, 종합안 최종
반박 1개로 총 13개 별도 작업 문맥을 사용했다. 원래 90개 주장·제안, RED 4개,
DEF 1개의 **95개 추적 항목**을 [판정 원장](decisions.md)에 유지했다. 이 수는 중복
원인·문서 과장·조건부 위험·제품 선택을 포함하며 결함 수가 아니다.
종합안의 [최종 반론 12개](13-final-challenge.md)에도 [항목별 응답](14-final-response.md)을
남겨 [개선 계획](plan.md)과 원장을 정정했다. 제품 구현·릴리스 완료를 뜻하지 않는다.

## 종합 판단

원래 방향을 버리고 다시 만들 근거는 찾지 못했다. Markdown 원본, 재구축 가능한
검색 캐시, 인간/agent 읽음 분리, 페이지를 곧바로 덮지 않는 웹 제안 큐는 보존과
LLM 판단의 역할 분담에 맞는 설계다. 우선 수리할 것은 **성공 응답의 보존 책임,
실패 뒤 실제 적용 상태, 현재 원문과 검색 근거의 연결, 실행 가능한 지침**이다.

최종 새 fixture에서도 서로 다른 HTTP 제안 32개가 모두 303을 받았지만 전문은
26개만 남았다. 원 페이지는 그대로였다. 로컬 두 clone의 sync는 충돌 marker를
원격에 발행하고 성공을 반환했지만 양쪽 원문은 stash/이전 commit에서 복구 가능했다.
이 관측은 [최종 재현](13-final-challenge.md)에 있으며 실제 사용자 발생률이나
Git 원문의 복구 불능 소실로 일반화하지 않는다.

| 우선순위 | 확인한 문제 | 제안 |
|---|---|---|
| 첫 문서 변경 | 웹 접수/반영, 공통 gate, done 검증, 로그 복구, wiki 선택을 강하게 또는 다르게 설명 | 두 스킬과 현재 사용자 안내를 사실·행동·완료 조건 중심으로 개정하고 영어 미러를 함께 맞춤 |
| 보존 결함 | 동시 제안 소실, autostash 충돌 발행, archive 덮기, 쓰기 중 원문 절단, 손상 checkout meta 뒤 사본 덮기 | 실패 재현을 먼저 고정하고 적용 구간·완전 게시·no-clobber·복구 상태를 최소 범위로 수리 |
| 검색 근거 | 빈 본문의 옛 청크, 소비 경로별 stale 결과, 원문 slice 불일치·profile 미식별 | 현재 출처와 profile의 유효성을 구별하고 cold/부분 실패를 정확히 표시 |
| 웹 작업 흐름 | 거짓 읽음 성공·추천0의 거짓 완료, 제안과 반영의 혼동, 실제 화면 검증 부족 | 상태를 정정한 뒤 밀도 높은 작업 도구로 조정하고 실제 브라우저에서 확인 |

보안 영향·미래 호환성·큰 위키 비용은 조건과 증거를 함께 남긴다. 현재 모델의 품질이
나쁘다거나 모바일 UI 전반이 고장났다는 결론은 내리지 않는다. DB/CRDT/ANN 전환,
모델 즉시 재수출, 스킬 전면 분할처럼 큰 처방은 작은 수정의 선결 조건으로 삼지 않는다.

## 읽는 순서

이 요약에서 범위와 핵심 결정을 보고, 개선 계획에서 작은 변경 묶음과 수용 조건을
확인한다. [결정표](decisions.md)와 [기계 원장](adjudication.json)에는 각 ID의 주장과
수정안 판정을 따로 남긴다. 종합안의 변경 이유는 최종 반박과 응답에서 확인한다. 원 보고서의
초기 심각도는 반박·재반박 뒤 조정할 수 있으므로 그대로 최종 결론으로 사용하지 않는다.

| 영역 | 독립 검토 | 주요 범위 |
|---|---|---|
| 원문·Git·쓰기 | [01-data](01-data.md) | 페이지/링크/YAML, sync, 부분 실패, checkout, 생성 index·로그 |
| 검색·근거 | [02-search](02-search.md) | chunk, FTS/vector/cache, engine, recall·bridge, 품질·비용 |
| 웹 | [03-web](03-web.md) | Handler/auth/render/JS/CSS/templates, 요청·상태·작업·접근성 |
| 재현 불가 상태 | [04-state](04-state.md) | 설정/이행, tasks/reads/attention/resurface/digest/reconcile |
| 문서·스킬 | [05-docs](05-docs.md) | 30개 Markdown 문서, 두 내장 스킬·설치 코드, 50개 help 표면 |
| 검증·배포·자산 | [06-ops](06-ops.md) | 테스트, CLI, Makefile/CI/release/tap, ORT/native/model/vendor/spike |

각 보고서는 읽은 파일, 실행한 사례, 미실행 범위, 반론, 수정 대안, 미래 수용 검사를
구별한다. 보존한 재현 소스·출력은 [evidence](evidence/)에 있다. `.go.txt`는 증거
소스이며 기본 테스트에 편입된 구현이 아니다. 실행할 때는 보고서의 독립 fixture
절차를 따르고 다른 검토자의 임시 경로를 덮어쓰지 않는다.

## 기준선과 검증 한계

[기준선](00-baseline.md)의 일반 Go 테스트·race 검사·포맷·18개 JS 테스트·i18n·lite
빌드/강등은 통과했다. [운영 검토](06-ops.md)는 추가로 lite 4개 OS/arch 컴파일과
이 머신의 ORT 빌드·실제 추론을 확인했다. 컴파일은 다른 플랫폼의 실행 확인이 아니며,
3문장의 ORT smoke는 공식 pooling 적합성이나 일반적인 검색 품질 평가가 아니다.

실제 브라우저 표면이 제공되지 않아 모바일 배치·paint·focus·접근성·브라우저 공격의
성립을 검증하지 못했다. HTTP·렌더 전달문·가짜 DOM 관측으로 확인한 부분과 이를
구분한다. 실제 Homebrew 설치·새 릴리스·전원 장애·장기간 다중 clone 운용도 이번
감사에서 실행하지 않았다. 큰 위키 수치는 합성 corpus의 관측이며 사용자 위키의
현황이나 보편적인 SLO로 해석하지 않는다.

이번 감사에서는 기존 코드·추적 문서·운영 서비스를 변경하지 않았고 실제 사용자
위키를 읽거나 쓰지 않았다. 감사의 새 파일은 이 디렉토리에 뒀다. canopy 재현의
HOME·XDG는 임시 경로이며,
기준선 테스트 helper·SDK의 HOME 기록에 대해 더 강한 격리를 주장하지 않는다.
해당 제한과 테스트 격리 관측은 기준선과 OPS-06에 적었다.

## 토론과 최종 판정

데이터/상태, 검색/운영, 웹/문서의 세 묶음을 새로운 검토자가 반박하고, 다시 별도의
참여자가 증거를 재검증해 재반박했다. 마지막으로 종합 판정과 PLAN 14개 전부 및
하위 처방·수용 조건을 새 검토자가 반박했다. 여기서 독립은 새 작업 문맥과 별도
증거 검사를 뜻하며 서로 다른 모델·사람의 검토를 뜻하지 않는다. 반박에서 나온
신규 주장에도 식별자와 응답을 남겼다. 보류·기각·의견 차이를 지우지 않고,
확인한 사실과 채택한 수정안을 따로 결정했다.

| 토론 묶음 | 반박 | 재반박 |
|---|---|---|
| 원문·상태 | [07-red-data](07-red-data.md) | [10-defense-data](10-defense-data.md) |
| 검색·운영 | [08-red-search](08-red-search.md) | [11-defense-search](11-defense-search.md) |
| 웹·문서 | [09-red-web-docs](09-red-web-docs.md) | [12-defense-web-docs](12-defense-web-docs.md) |

최종 반론은 실패의 게시 경계·동시 쓰기 oracle·JSON 실패 행렬·same-version unknown·
미지원 embedding 설정·사전 사본 보존·선택 UI 범위·평가 종료·우선순위 그림을
정정하게 했다. DATA-04 중간 판정과 A3의 B·C 이견은 유지했다. 신규 DEF-A-01은
조건부 1일 snooze 즉시 만료로 채택했고 literal 7일 E4 실패로 부풀리지 않았다.

ID 누락 검사 [check-review.py](evidence/check-review.py)는 표의 참조 누락을 확인하는
보조 도구다. ID가 등장했다는 사실은 반박의 충실도나 판정의 옳음을 증명하지 않는다.
각 토론 표와 코드·재현 자료를 함께 읽어야 한다.

최종 [ID 검사](evidence/root-coverage.json), [링크·fence·Mermaid QA](evidence/root-report-qa.json),
[소스·입력·작업 자원 보존 검사](evidence/root-final-integrity.json)에 실제 범위를 남겼다.
미래 구현은 선택한 불변식·실행 점검·실패 재현·수용을 먼저 연결하고 F1/F2/F3와
해당 i18n 규칙을 지켜야 한다. 미구현 선택 기능을 이번 감사의 실패로 세거나,
미실행 검사를 합격으로 세지 않는다.
